# Broker integration status and callback gateway

Upstox has a code-level OAuth authorization/code-exchange/profile adapter. Official references checked: https://upstox.com/developer/api-documentation/authentication/ , https://upstox.com/developer/api-documentation/get-token/ , https://upstox.com/developer/api-documentation/get-profile/ . Its documented token boundary is modeled at the next 03:30 Asia/Kolkata. No refresh-token mechanism is assumed. HTTP contract tests use httpx.MockTransport; real customer authorization and provider sandbox verification have not been performed.

Dhan documentation was inspected at https://dhanhq.co/docs/v2/authentication/ and differs from Upstox; no Dhan adapter is implemented. Dhan, Zerodha, Angel One, FYERS, 5paisa and ICICI remain disabled pending independent documentation, app type, commercial/partner permissions, exact callback registration and account validation. No broker is marked production-ready. No live order adapter is registered.

Registry modes: DISABLED, PLATFORM, INDIVIDUAL, HYBRID. Existing rows default to DISABLED. Operator-only backend/configure_broker.py supports creating a reviewed Upstox auth registration; it requires --auth-reviewed and --evidence-reference, prompts or reads application credentials and refuses to overwrite existing integration secrets. Authentication review is separate from the 18-requirement production review.

Gateway: POST /api/v1/brokers/{broker}/connect or /reauthorize with mode and optional individual client credentials. GET /{broker}/callback resolves the owner from hashed, expiring, atomically consumed state. Token exchange is server-side; tokens are encrypted in a user/account-bound envelope. GET /connections and /{broker}/status return masked status. POST /{broker}/{account_id}/disconnect deletes local credentials/invalidates pending state but does not claim provider-side revocation. Account emergency stop is POST /{broker}/{account_id}/emergency-stop. Reauthorization repeats the official login flow; it is not token refresh.

Callbacks: https://api.gnkalgo.com/api/v1/brokers/{id}/callback, where ids are dhan, zerodha, upstox, angelone, fyers, 5paisa, icici. These are proposed GNK routes, not confirmation of broker registration. Only Upstox has an active adapter implementation, and it still requires operator enablement. Request/callback values are not logged by the supplied server configuration.

18-gate APIs are under /api/v1/admin/brokers/{broker}: approval, requirements, requirements/{number}/verify, production-status and production-approval. SUPER_ADMIN is required. Evidence records store a reviewer-attested reference, SHA-256, expiry and actor; external evidence content is not independently fetched/authenticated. The server rechecks every requirement and refuses live production approval because execution/reconciliation remain unavailable.
