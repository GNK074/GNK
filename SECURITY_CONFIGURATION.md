# Security configuration and operational boundaries

Argon2 user password hashes, short-lived cookie JWTs, rotating hashed refresh tokens, DB session revocation, CSRF, strict same-site cookies, CORS allowlist and backend RBAC remain in place. MFA uses encrypted TOTP seeds, enrollment-restricted sessions, a narrow time window and replay counters; confirming enrollment revokes other sessions. Password reset does not bypass existing MFA. Authenticator recovery codes and a reviewed lost-device recovery process are not implemented; establish an operator policy before requiring MFA for customers.

Broker token ciphertext binds user_id and account_id inside its encrypted payload. Client app secrets are encrypted separately. Never persist tokens in browser storage. Integrations cannot be enabled from frontend role changes. Callback state is hashed, short-lived and atomically consumed before external exchange. Failed exchange requires a new state. No broker passwords/PINs/OTPs are collected.

Runtime DB role is restricted, and new tenant tables use forced PostgreSQL RLS. Never expose DB/Redis ports or share runtime credentials with customers. Owner credentials mount only into PostgreSQL and the isolated migrator, not the API. secrets/ is 0700; generated individual mount files are 0444 so non-root container users can read the specifically mounted file; .env is 0600. Apply equivalent ACL protection on Windows. Compose file secrets are protected files, not an encrypted managed KMS vault.

For field-key rotation: take an encrypted backup, configure new FIELD_ENCRYPTION_KEY, retain prior keys in FIELD_ENCRYPTION_PREVIOUS_KEYS, increment ENCRYPTION_KEY_VERSION, then run rotate_field_keys.py --apply using reviewed maintenance credentials. Verify decryption of accounts/MFA before retiring old keys. Do not generate replacement keys over existing files. Database password rotation needs a coordinated PostgreSQL ALTER ROLE and secret-file update; regeneration alone does not rotate an existing role. JWT rotation invalidates access tokens; revoke sessions when responding to compromise.

Nginx logs exclude query strings/cookies/authorization headers; Uvicorn access logs are disabled. Do not enable debug/provider-response logging. Actual penetration testing, dependency audit, production load testing, managed secret storage and external security/compliance approval remain outstanding.
